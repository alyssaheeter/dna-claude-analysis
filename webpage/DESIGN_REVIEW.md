# DNA Terminal: design critique, plan and rubric

Reviewed: `webpage/dna_terminal.html` as generated by `scripts/generate_webpage.py` (desktop 1280px and mobile 390px, headless Chromium screenshots).
Audience: the genome owner, a non-specialist who wants to know what matters, what to do about it, and how far to trust it.

## 1. Critique

### Overall impression
Strong terminal identity, a clean and consistent component system, and honest disclaimers. But it is a **data dump, not an answer**: 108 markers across 16 sections, every one given the same visual weight, in jargon (rsIDs, gene symbols). The reader must do the triage themselves.

### What works
- Consistent components; green/amber/red semantics; sharp terminal look matches the brief.
- Status words sit next to colour, so status is not colour-only in the tables.
- "NOT ON CHIP" rows and the APOE/CYP1A2 notes are honest about coverage.
- Status box is derived from the genotypes, not hand-written.

### Findings
| Area | Finding | Severity |
|---|---|---|
| Answer-first | Top alerts are one flat, unprioritised list of 11. Real signal (CYP2C19 drug metabolism, BTBD9, 9p21, TCF7L2) is mixed with weak items (IL-1B, CTLA4, acne). No "what to do". | 🔴 |
| Actionability | Nothing says what to ask a doctor, pharmacist or lab. The only action text is generic. | 🔴 |
| Interpretability | Columns are SNP / Gene / Genotype. A lay reader cannot tell which result matters or how big the effect is. "MODERATE" has no definition and no legend. | 🔴 |
| Mobile | At 390px the page overflows horizontally (alert text clipped at the right edge) and the 3-row fixed nav covers the top of the content. Tables have no mobile layout. | 🔴 |
| Accessibility | `--gray` (#666) on #0a0a0a is 3.4:1 (fails 4.5:1) and is used for N/A status, labels and the progress label. Table headers are 10px, tables 12px. No focus styles, skip link, `aria-current`, or reduced-motion rule. The blinking logo cursor ignores `prefers-reduced-motion`. | 🔴 |
| Redundancy | The same IL-6 / BDNF / COMT / TNF rows repeat in up to 8 sections; the same long disclaimer repeats 9 times. | 🟡 |
| Navigation | 16 long, always-open sections; no "flagged only" view, no search, no collapse, no print layout (the page is the thing you would hand a clinician). | 🟡 |
| Honesty | Confidence is not shown. A weak-evidence domain (psychology, traits, chronotype) looks as authoritative as an established one (pharmacogenomics, Factor V). | 🟡 |
| Hierarchy | Status box competes with the section boxes; the first screen on mobile is only identity fields. | 🟡 |

## 2. Improvement ideas (brainstorm, ranked by value to the reader)
1. **Key takeaways panel** at the top, in tiers: *Ask about / act on*, *Worth knowing*, *Good news*, *Not tested*.
2. **"Questions for your clinician"** box generated from the flagged markers that have a standard follow-up (pharmacist note, 25(OH)D test, ferritin, screening).
3. **Evidence level per section** (Established / Moderate / Weak) so psychology and traits are not read like Factor V.
4. **Plain-English table**: lead with the meaning, rsID and gene secondary, a status icon plus word, a legend that defines each status.
5. **Flagged-only toggle, search box, collapsible sections** (flagged sections open, clean ones collapsed).
6. **Dedupe**: each gene gets one alert; repeated rows say "also in …".
7. **Not-tested tracker**: what this chip cannot tell you and where to get it (clinical test).
8. **Mobile**: one-row scrollable nav, table to stacked-card layout, no horizontal overflow.
9. **Accessibility pass**: contrast, min font sizes, focus rings, skip link, `aria-current`, reduced motion.
10. **Print stylesheet**: everything expanded, light background, no-break rows. Save as PDF for the clinician.
11. **Provenance footer**: source file, generated time, limits, how to confirm in a clinical lab.
12. One disclaimer up front plus short per-section evidence badges, instead of nine copies.

Rejected: charts/gauges/scores (would imply precision the single-SNP data does not have); a polygenic "risk score" (same reason); external JS libraries (CLAUDE.md: single file, no dependencies except Google Fonts).

## 3. Rubric (score each category 1–5; target 5 in every category)
Scores are verified by the check named in the last column, not by impression.

| # | Category | A 5 means | Check |
|---|---|---|---|
| R1 | Answer-first clarity | In the first screen (desktop and mobile) the reader sees the prioritised takeaways in tiers, ≤7 items in the top tier, each de-duplicated by gene | Screenshot at 1280×900 and 390×844; count items; no gene appears twice in takeaways |
| R2 | Actionability | Every top-tier item carries a concrete "ask/do" line, and a single clinician-questions list exists; no line is phrased as a diagnosis or dose instruction | Review all `act` strings; grep for forbidden phrasing |
| R3 | Interpretability | Each table row leads with plain-English meaning; a legend defines every status; jargon (rsID/gene) is secondary | Header text, legend present, status icon+word on 100% of rows |
| R4 | Evidence honesty | Every section shows an evidence level; coverage gaps listed; one general disclaimer at the top plus the two section-specific warnings (pharma, carrier) and a footer; VERIFY items stay flagged; no unsupported numbers | Count evidence badges = sections; count disclaimer boxes ≤3 (wording clarified after planning: 1 general + 2 critical); summaries derived from genotypes |
| R5 | Navigation & findability | Flagged-only toggle, search, collapsible sections, anchor nav with `aria-current`; repeated markers de-duplicated or cross-referenced | Manual script: toggle hides all non-flagged rows; search reduces rows; anchors resolve |
| R6 | Visual hierarchy & scanning | One clear first focal point; three-tier type scale; flagged rows stand out from clean ones without relying on colour alone | Screenshot review; flagged rows carry icon and bold weight |
| R7 | Accessibility (WCAG 2.1 AA) | All text ≥4.5:1; body text ≥13px, nothing under 12px; focus-visible rings; skip link; landmarks; reduced-motion honoured; status not colour-only | Computed contrast of every colour pair; computed font sizes via DOM; tab-order check |
| R8 | Responsive & print | No horizontal scroll at 390px; fixed header never covers content; tables become cards on mobile; print stylesheet expands all sections on white | Headless DOM check `scrollWidth <= innerWidth` at 390 and 320; print screenshot |

Gate: do not implement until the plan below is mapped to a 5 in every category (section 4). After implementing, re-score from the checks; any category under 5 gets another iteration.

## 4. Implementation plan, mapped to the rubric
Changes live in `scripts/generate_webpage.py` (extra CSS/JS appended to the CSS borrowed from `webpage/example.html`); `example.html` stays untouched.

| Step | Work | Closes |
|---|---|---|
| P1 | Add per-row `act` (follow-up text) and `tier` metadata to the interpretation tables for the markers that warrant it; everything else stays untiered | R1, R2 |
| P2 | Build takeaways from rows: tier 1 *Ask about* (≤7, de-duplicated by gene), tier 2 *Worth knowing*, *Good news*, *Not tested*; clinician-questions list from `act` | R1, R2 |
| P3 | Table: lead column "What it means", then "Your result" (genotype) and small "Marker" (gene · rsID); status icon+word; legend box defining Typical / Slightly elevated / Elevated / Info / No interpretation | R3, R6 |
| P4 | Section evidence badge from a fixed map (pharma, health-established markers = Established; psych/cognitive/traits/chronotype/ancestry = Weak; rest Moderate) with a one-line meaning; one full disclaimer up front, short footer note | R4 |
| P5 | `<details>` sections (open if flagged), flagged-only toggle, search input, `aria-current`, skip link, cross-reference "also in" for repeated gene rows | R5 |
| P6 | Raise text contrast (`--gray` text to ≥4.5:1), table 13px and headers 12px, focus-visible rings, reduced-motion, landmarks and ARIA labels | R7 |

## 5. Result after implementation
Measured by `node scripts/check_webpage.js` (Playwright + Chromium; 31 automated checks) plus screenshot review at 1280, 390 and 320px and a print-to-PDF render.

| Category | Baseline | Result | Evidence |
|---|---|---|---|
| R1 Answer-first clarity | 2 | 5 | 6 tiered takeaways (limit 7), no repeated gene; 6 visible on the 1280×900 first screen, 2 on 390×844 |
| R2 Actionability | 1 | 5 | every top-tier item has an ask/do line; separate clinician-question list; no dose or diagnosis phrasing (regex check) |
| R3 Interpretability | 2 | 5 | plain-English lead column, legend, icon + word on 108/108 rows |
| R4 Evidence honesty | 3 | 5 | 16/16 evidence badges, 3 disclaimer boxes, not-tested list, derived summaries, footer provenance |
| R5 Navigation & findability | 3 | 5 | search, flagged-only, collapse/expand, nav jump opens section and sets `aria-current`, 47 "also in" cross-references |
| R6 Visual hierarchy | 3 | 5 | takeaways are the first focal point; flagged rows bold + icon; amber rail on the top tier (screenshot review) |
| R7 Accessibility | 2 | 5 | all visible text ≥4.5:1 (computed per element), nothing under 12px, table body 13px, skip link first Tab stop, focus rings, reduced motion |
| R8 Responsive & print | 2 | 5 | no horizontal scroll at 1280/390/320, header never covers content, stacked cards at ≤640px, white print layout verified |

Two things the script cannot prove, so they are judgement and are listed here rather than hidden:
- The per-section evidence levels (Established / Moderate / Weak) and the follow-up wording are my curation from general knowledge, not from a cited guideline per marker. Treat them as reasonable defaults and edit `EVIDENCE` and `ACT` in `scripts/generate_webpage.py` if you disagree.
- "Single focal point" (R6) comes from reading the screenshots.

Re-run: `cd scripts && python3 generate_webpage.py && cd .. && node scripts/check_webpage.js`
